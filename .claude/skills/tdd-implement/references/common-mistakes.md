# よくある間違い

| 間違い                                                       | 対処                                                                              |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| テストを書く前に実装する                                     | test-driven-development に従い、必ず RED を確認してから実装                       |
| 独立タスクを同一ツリーで並列実行してファイル衝突             | worktree で隔離して並列（重なるなら逐次）                                         |
| worktree のコミットや `main` へのコミットを残す              | コミットせず差分(patch)で統合。完了後も commit しない                             |
| 検証せずに「完了」と言う                                     | verification-before-completion: コマンドを実行し出力で裏付ける                    |
| テスト失敗を場当たりで直す                                   | systematic-debugging: 根本原因→失敗テストで再現→単一修正                          |
| 計画/設計を勝手に変える                                      | 先に AskUserQuestion で許可。許可後に docs を更新                                 |
| `.claude/rules/test.md` が無いからとテスト方針を自己流にする | `CLAUDE.md` の Testing 方針にフォールバック                                       |
| 受け入れ条件を確認しない                                     | 計画の受け入れ条件を1項目ずつチェック                                             |
| RED 確認後にロックせず、後でテストを書き換える               | RED 確認後に `.tdd-lock` へ追記。改変が要るなら理由を述べユーザー許可（一時例外） |
