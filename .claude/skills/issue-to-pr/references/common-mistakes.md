# よくある間違い

| 間違い                                           | 対処                                                           |
| ------------------------------------------------ | -------------------------------------------------------------- |
| 計画承認の前にファイルを書く / 実装に入る        | 保存・実装は `ExitPlanMode` 承認後。plan mode 中は書かない     |
| 実装中に逐次承認を求める                         | 人間ゲートは plan 承認の1点。承認後は auto mode で自走         |
| main 上で実装・コミットする                      | `create-branch` のブランチ上で実装し、`commit` → `create-pr`   |
| 1 起動で複数 issue を処理する                    | 1 起動 = 1 issue = 1 PR。複数は扱わない                        |
| ready でない issue を無人で進める                | ready が無ければ警告・確認。未 refine は `refine-issue` へ     |
| PBI（アンブレラ）に本ループを回す                | 実装単位向け。`refine-issue` で分割し subtask/技術タスクに回す |
| 設計判断が無いのに ADR を作る                    | ADR は設計判断があるときだけ。無ければ計画のみ                 |
| ロック済みテストをレビュー対応で書き換える       | `.tdd-lock` 済みは触らない。必要なら停止して人へ               |
| 設計級の指摘を無人で判断する                     | 停止して人へ報告（draft PR ＋ メモ可）                         |
| PR を自動マージする                              | 対象外。マージは人                                             |
| `commit` スキルに `git add` させようとする       | `commit` は add しない。先に `git add -A`                      |
| brainstorming/writing-plans が既定の保存先に書く | `docs/adr`・`docs/features` へ上書き（承認後に保存）           |
