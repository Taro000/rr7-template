# よくある間違い

| 間違い                                              | 対処                                                         |
| --------------------------------------------------- | ------------------------------------------------------------ |
| `AskUserQuestion` / `ExitPlanMode` で人の応答を待つ | 無人。判断できなければ記録して終了（→ SKILL.md `## 失敗時`） |
| `ready for dev` が無い issue を進める               | ガードで issue コメントを残して終了                          |
| PBI（アンブレラ）に本ループを回す                   | 実装単位向け。分割を促すコメントを残して終了                 |
| ペイロード本文だけで実装に入る                      | 切り詰めの可能性あり。`gh issue view` の最新本文を正とする   |
| 設計判断を無人で下す / 新規発明する                 | issue・既存 ADR に答えが無ければ分析を残して終了             |
| テスト失敗を 4 回以上修正し続ける                   | 同一の失敗は 3 回まで。超えたら draft PR ＋ コメントで終了   |
| ロック済みテストを書き換える / ロックを外す         | `.tdd-lock` 済みは触らない。必要になったら記録して終了       |
| 黙って終了する（コメントを残さない）                | 終了時は必ず issue / PR コメントに状況を記録                 |
| ローカルの対話セッションで本スキルを使う            | ローカルは `issue-to-pr`（plan 承認の人間ゲートあり）        |
| 1 起動で複数 issue を処理する                       | 1 起動 = 1 issue = 1 PR。複数は扱わない                      |
| main 上で実装・コミットする                         | `create-branch` のブランチ上で実装し、`commit` → `create-pr` |
| PR を自動マージする                                 | 対象外。マージは人                                           |
| 設計判断が無いのに ADR を作る                       | ADR は設計判断があるときだけ。無ければ計画のみ               |
| `commit` スキルに `git add` させようとする          | `commit` は add しない。先に `git add -A`                    |
