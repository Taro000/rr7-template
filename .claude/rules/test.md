# テスト戦略規約

> いつ読むか: テストを書く前、テストの種類・粒度・命名・配置・カバレッジ方針を決めるとき。`tdd-implement` スキルは本ファイルをテスト戦略・テストコマンドの正として読む。

## 基本方針

- **TDD**: 実装前にテストを書く。テスト先行 → RED（失敗確認）→ 最小実装 → GREEN → REFACTOR。
- テストは「実装のゴール＝仕様」と捉え、**ファイル名は `*.spec.ts` / `*.spec.tsx`**。
- **テストタイトル（`describe` / `it`）は日本語で書く。** テストは仕様であり、母語のほうが意図が正確に伝わる（lint で機械強制）。
- **コロケーション**: テストはテスト対象と同じディレクトリに置く（例: `Counter.tsx` の隣に `Counter.spec.tsx`）。
- UI コンポーネントとロジックで戦略を変える（下記マトリクス）。

> テストは `*.spec.{ts,tsx}` に統一する。**`*.test.{ts,tsx}` は lint で禁止**（`arch/no-test-file`）。

## テストマトリクス

|                      | ユニット                                     | インテグレーション                                         |
| -------------------- | -------------------------------------------- | ---------------------------------------------------------- |
| **ロジック**         | 副作用・依存のない純粋関数の入出力の期待値   | 複数関数からなる依存・副作用ありの複合処理の入出力の期待値 |
| **インタラクション** | 依存のない単純な UI コンポーネントの振る舞い | ページ/セクション等、複数 UI から構成される UI の振る舞い  |

## 性質とカバレッジ

- **ロジックテスト**: ホワイトボックス許可。**C0 / C1 カバレッジ 100% を目標**。
- **インタラクションテスト**: ブラックボックス（内部実装を知らない＝疎結合）。次の観点でケースを作る。
  - **ユースケースカバレッジ**: props の値・公開ハンドラによる表示の変化
  - **状態カバレッジ**: 内部状態による表示の変化
  - **要件カバレッジ**: 同値クラス（正常 / 異常）/ 境界値 / ビジネスルール

## ツールとコマンド

- ランナー: **vitest**（jsdom + `@testing-library/react`、globals 有効、`vitest.setup.ts` で jest-dom 登録・各テスト後 `cleanup()`）。
- コマンド: 全実行 `npm test` / 単一 `npx vitest run app/path/Name.spec.tsx`（`-t "名前"` 絞り込み）/ watch `npm run test:watch`。
- インタラクションは `@testing-library/react`（`render` / `screen`、role・label クエリ）＋ `@testing-library/user-event`。内部（state 変数名等）に依存しない。

## E2E（ブラウザ確認）

- 実ページ遷移・ブラウザ挙動は **Playwright-cli**（`playwright-cli` スキル）で確認。
- **CI には組み込まない**（時間がかかるため）。明示実行のテストとする。
- AI は実装後に Playwright-cli で自ら確認する。
